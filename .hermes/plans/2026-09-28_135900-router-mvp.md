# Support-Triage Router (MVP) Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** A Python CLI that routes free-text support tickets (may embed JSON logs, YAML, stack traces) through a Jev decision call to one of four specialized CrewAI crews, with a confidence gate to human review, evaluated against the approved 24-ticket synthetic dataset.

**Architecture:** Deterministic Python owns the workflow: intake/state-builder (with credential redaction) → one Jev decision request over OpenRouter (`/api/alpha/decisions`, `typesafe/jev-1.13`) → code composes typed answers (weights as named constants) → confidence gate → dispatch to a CrewAI crew (default LLM `z-ai/glm-5.3-flash` via OpenRouter) or review queue. The router itself is NOT an agent.

**Tech Stack:** Python 3 (stdlib core), `crewai[tools]` for crews (lazy-imported, isolated seam), OpenRouter for both Jev decisions and chat models, `uv` for env management, `unittest` for tests (host venv is stdlib-only: no pandas/pytest), ruff for lint, GitHub Actions CI (keyless, every PR).

## Flow diagram

```
tickets.jsonl
     │
     ▼
intake/state builder ── redaction of credential-looking tokens
     │  (features: fenced json/yaml blocks, stack traces,
     │   log lines, keywords, customer tier, urgency markers)
     ▼
Jev decision call — ONE request, questions answered in parallel
     ├─ noul   : is_churn_risk, is_payment_issue, is_credential_exposure,
     │           is_urgent_deadline, is_how_to_question
     ├─ choice : route ∈ {billing, technical_bug, escalation, faq}
     └─ score  : severity (0–1 normalized + legend → priority 1–4)
     │
     ▼
compose in code (weighted signals, named constants)
     │
     ├── confidence ≥ gate AND route resolvable
     │        └──► dispatch CrewAI crew for that route
     └── confidence < gate OR insufficient_info / credential exposure
              └──► review queue (requires_human, never guessed)
```

## Jev request contract (exact)

```
POST https://openrouter.ai/api/alpha/decisions
Authorization: Bearer $OPENROUTER_API_KEY
{"model": "typesafe/jev-1.13",
 "state": {"ticket": {...derived features...}, "customer": {...}},
 "questions": {
   "route":     {"type": "choice",
                 "instructions": "Which workflow should own ticket `ticket.id`?...",
                 "criteria": {"billing": "...", "technical_bug": "...",
                              "escalation": "...", "faq": "..."}},
   "severity":  {"type": "score",
                 "instructions": "...",
                 "criteria": [ {"what": "low",  "signals": [...]},
                               {"what": "medium", "signals": [...]},
                               {"what": "high",  "signals": [...]},
                               {"what": "critical", "signals": [...]} ]},
   "is_churn_risk":         {"type": "noul", "instructions": "...",
                             "criteria": {"true": {"what": "..."}, "false": {"what": "...", "not_for": "..."}}},
   "is_payment_issue":      {... noul ...},
   "is_credential_exposure":{... noul ...},
   "is_urgent_deadline":    {... noul ...},
   "is_how_to_question":    {... noul ...}
}}
```

Response parsing (defensive, per-question): answers at `response.answers.<name>`; `route` answer → option + `confidence` (if present); `severity` → normalized 0–1 `score` + `legend` dict mapping "0".."4" to levels. Priority conversion: the API may return a 5-bucket `legend` mapping "0".."4" even when `criteria` has 4 levels. Resolve as: bucket = min(4, floor(score*5)); take that legend level's `what` label; use it as priority only if it matches `low|medium|high|critical`; otherwise — and whenever `legend` is absent or malformed — treat `severity` as a FAILED/missing answer for that record (never compute `score*4+k` arithmetic fallbacks). A missing field fails that record only, never the run; the missing-answer rule routes it to review.

## Composition + confidence gate (named constants, tunable in code)

```python
CONFIDENCE_GATE = 0.70          # below -> review
SEVERITY_WEIGHT = 0.6           # weights sum-able; tune here, not in prompts
NOUL_SIGNAL_WEIGHTS = {
    "is_churn_risk": 0.15, "is_payment_issue": 0.10,
    "is_credential_exposure": 0.25, "is_urgent_deadline": 0.15,
 }
 # is_how_to_question intentionally unweighted here: it informs faq route
 # selection and the fake provider, not severity/confidence weighting.
CREDENTIAL_EXPOSURE_FORCES_REVIEW = True
```

- **Confidence source (pinned):** the gate consumes the `route` answer's `confidence` when present; if absent, use the MINIMUM confidence across the answered questions; if no answered question carries `confidence`, the record goes to review (unknown confidence = no confidence).
- `RouteDecision(ticket_id, route, priority, confidence, dispatch|review, reasons[])`
- `requires_human = (confidence < gate) or noul(is_credential_exposure) or answer missing`
- `ambiguity: insufficient_info` in `expected` is only for eval scoring; the router has no access to `expected`.
